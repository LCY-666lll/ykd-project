# 组合型文件生成工具链设计

## 目标

补齐“查询或计算后生成文件”的组合请求，使天气、新闻、时间、翻译和精确计算结果能够继续复用现有 Spring AI `@Tool`，并由现有 `FileGenerationTool` 输出 PDF、DOCX 或 XLSX。

典型请求：

- 把北京未来三天天气生成 PDF。
- 查询今天的新闻并整理成 Word。
- 计算 `(100+25)*3/2` 后生成 Excel。
- 把上文翻译成英文并导出 DOCX。

## 约束

- 不改变 `IlinkMessagePollingService → IlinkMessageReplyServiceImpl → DeepSeekIntentRouter → IlinkReplyProcessor → IlinkReplySender` 主链路。
- 不增加统一任务规划器，不将文件二进制生成改成模型工具调用。
- 继续由 `DeepSeekIntentRouter` 识别 `FILE_GENERATE`，由 `IlinkReplyProcessor` 直接调用 `FileGenerationTool`。
- 继续复用现有 `WeatherTool`、`BaiduSearchTool`、`TimeTool`、`TranslationTool` 和 `MathCalculatorTool`。
- 用户明确指定的文件格式仍由 `resolveTypes` 做最终兜底，不依赖模型猜测。

## 方案

### 依赖与注册

在 `FileGenerationTool` 中注入现有五类文本工具，并在生成文件草稿的 `ChatClient` 请求上统一注册：

- `search_realtime_information`
- `query_current_weather`
- `query_weather_forecast`
- `get_time_info`
- `translate_text`
- `calculate_math_expression`

不新建工具注册器。本次只有普通文本聊天和文件草稿生成两个调用方，直接复用现有 Bean 更符合最小改动原则。

### 文件草稿提示词

在现有文件草稿提示词中增加明确的工具选择规则：

- 当前、实时天气调用 `query_current_weather`。
- 今天至后天、未来三日预报调用 `query_weather_forecast`。
- 新闻、时事、最近或指定日期信息调用 `search_realtime_information`。
- 精确算式调用 `calculate_math_expression`。
- 当前日期时间调用 `get_time_info`。
- 明确翻译请求调用 `translate_text`。

工具失败时必须在文件内容中如实说明失败，不得使用训练数据伪造实时结果。模型最终仍只返回原有 `FileDraft` JSON 结构。

### 数据流

```text
用户组合请求
  → DeepSeekIntentRouter：FILE_GENERATE
  → IlinkReplyProcessor
  → FileGenerationTool
      → 按需要调用现有 @Tool
      → 生成一次 FileDraft
      → resolveTypes 确定目标格式
      → 现有 PDF/DOCX/XLSX 渲染代码
  → ReplyResult.DOCUMENT
  → IlinkReplySender.sendFile
```

## 错误处理

- 工具参数和业务错误继续沿用各工具现有异常处理。
- `FileDraft` 为空或内容为空时继续抛出原有 `BusinessException(50006)`。
- 文件渲染失败继续沿用各格式现有异常。
- 不在本次增加自动重试、熔断或新的降级框架，避免同时改变功能链和基础设施。

## 测试

1. 验证 `FileGenerationTool` 的 Spring AI 请求注册了完整工具集合。
2. 验证天气预报生成 PDF 时能够使用天气预报工具，而不是普通文本模型自行编写数据。
3. 验证新闻生成 DOCX 继续使用实时搜索工具。
4. 验证精确计算生成 XLSX 能调用计算工具。
5. 保留现有文件格式解析测试，确保明确格式优先。
6. 执行 `mvn -q clean test` 和 `mvn -q -DskipTests compile`。

## 非目标

- 不升级复杂模板、图表、主题样式和办公文档排版。
- 不重构 `FileGenerationTool` 为多个渲染服务。
- 不修改图片、语音和普通文本回复链路。
- 不引入 Redis、消息队列或新的模型。
- 不调整外部接口超时、重试、熔断和限流策略。
