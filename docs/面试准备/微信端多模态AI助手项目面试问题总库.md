## 工具调用答题基准（2026-08-08 用户指定重点参考）

### 开场总问题：你项目里的工具调用总链路是什么？

回答必须先讲框架如何识别工具能力，再讲处理链路，推荐按五段展开：

1. **工具注册**：项目把工具实现为 Spring Bean，在 Java 方法上使用 `@Tool(name, description)`，参数使用 `@ToolParam`。`AiChatServiceImpl` 调用 `ChatClient.prompt().tools(...)` 传入工具对象后，Spring AI 根据这些方法生成 `ToolCallback` 和 `ToolDefinition`，其中包含工具名、描述和根据方法签名生成的参数 JSON Schema。这里的本质是框架把普通 Java 方法转换成模型可识别的函数定义。
2. **模型识别与决策**：Spring AI 把工具定义放进模型请求。模型结合系统提示词和工具描述判断是否需要工具；需要时返回结构化的工具调用请求，即工具名和参数 JSON。模型只负责决策，不直接执行 Java 代码。
3. **框架分发执行**：`ToolCallingManager` 根据工具名找到对应 `ToolCallback`，把参数 JSON 转换成 Java 方法参数并调用真实工具方法。天气工具会继续调用 `WeatherService/QWeatherClient`，搜索、时间、翻译和计算工具分别进入各自实现。
4. **结果回传**：工具返回值被框架包装成工具响应消息，追加到当前 Prompt 后再次调用模型。模型基于真实工具结果生成最终回答，也可以继续请求下一个工具。
5. **循环终止与项目增强**：模型不再返回工具调用时循环结束。项目通过继承 `ToolCallAdvisor` 的 `ReActTraceAdvisor` 记录 START/ACTION/OBSERVATION/FINAL 轨迹、限制普通对话最多 8 轮、对日志和工具结果脱敏，并将证据型工具结果沉淀为【工具依据记忆】。

面试口语化总结：`@Tool` 声明能力 → Spring AI 转成 `ToolCallback/ToolDefinition/JSON Schema` → 模型返回工具名和参数 → `ToolCallingManager` 调用真实 Java 方法 → 工具结果回传模型 → `ToolCallAdvisor` 驱动循环，直到模型输出最终回答。

### 第 21 题参考骨架：哪些类串起完整工具链？

外层回答先说清主链：`AiChatServiceImpl` 发起 ChatClient 请求并注册五个工具 → `SpringAiChatConfig` 创建的主 `ChatClient` 提供三个 Advisor → `ReActTraceAdvisor/ToolCallAdvisor` 驱动工具循环 → `ToolCallingManager` 匹配并执行工具 → 工具结果回传模型 → 模型生成最终回答。随后再分别回答 ChatClient 在哪里创建、工具在哪里注册、Advisor 在哪里加入、工具结果如何返回模型。

### 第 22 题参考骨架：Spring AI Tool Calling 是怎么接入的？

外层回答先强调“模型决策、框架执行”：`@Tool/@ToolParam` 声明 Java 工具 → Spring AI 生成 `ToolCallback` 和参数 Schema → `.tools(...)` 把工具定义提供给模型 → 模型返回结构化工具调用 → `ToolCallingManager` 匹配并执行 Java 方法 → 工具结果作为工具响应消息回传模型。回答子题时再区分 `ToolCallback` 与普通 Service 方法，并明确模型本身不会执行 Java 代码。

## 简历·本项目部分（2026-08-05 用户提供，原文保存）

优课达（杭州）网络有限公司 2026-06 ~ 2026-08 Agent开发实习生（实习小组组长）杭州

微信端多模态 AI 助手 项目背景：面向微信用户构建 AI 助手，支持实时信息查询、图片理解与生成、文件生成、语音回复、公开网页操作及跨会话个性化对话；将大模型、Function Calling、MCP 浏览器和长期记忆接入微信消息链路，实现自然语言请求、工具执行与结果返回闭环。

- ReAct 式 Agent 与工具编排：针对大模型无法可靠获取天气、新闻、时间等实时信息，以及连续工具调用可能陷入重复循环的问题，基于 Spring AI Tool Calling 构建"模型决策—工具执行—结果回传—最终回答"流程，并通过自定义 Advisor 记录工具调用轨迹；接入联网搜索、实时天气、时间、翻译等工具，要求实时请求在本轮重新调用工具，并将单轮工具调用上限设为 8 轮，避免历史结果污染当前回答和工具异常循环
- MCP 浏览器任务与安全控制：针对普通搜索无法完成网页点击、筛选和翻页等动态任务的问题，基于 Spring AI MCP Client 对接 Playwright MCP，实现通过微信自然语言操作公开网页；校验 HTTP(S) 协议并拦截非公网地址、12 个工具白名单与 5 秒操作/30 秒导航超时，支持导航、快照、点击和信息提取，同时限制登录、支付、上传及脚本执行等高风险行为。
- 个性化长期记忆与向量召回：针对原始会话记录难以沉淀用户长期偏好，且全量拼接易造成上下文膨胀的问题，采用"会话记录 + 长期记忆"分层机制：SQLite 持久化原始会话，短期上下文仅加载最近消息；通过"记忆提取—历史记忆语义比对—新增/保留/替换/删除"两阶段模型调用，自动沉淀用户偏好等长期事实。将长期记忆生成 Embedding 后写入 Redis Stack 向量索引，按相似度召回候选记忆并回查 SQLite 完整记录。
- 异步解耦与主链路优化：针对主回复之外的记忆提取、语义合并及向量索引同步占用回复链路的问题，拆分"回复—记忆—索引"三段执行链路；主回复优先处理当前 Agent/MCP 任务并返回结果，记忆形成在后台执行，索引任务通过 Outbox 异步同步至 Redis，避免辅助任务阻塞当前微信交互。
- 团队协作与交付：担任实习小组组长，负责任务拆分、Git 分支管理、代码合并及冲突协调；组织 MCP、记忆系统等模块联调、定向测试与 Maven 编译验证，保障多人并行开发下主分支可构建、核心链路可回归。
